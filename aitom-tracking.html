📖 사용방법
  1. 이름 선택 — 우측 상단에서 본인 이름을 고르세요 (로그 작성 시 담당자로 기록)
  2. 확인 후 표기 — 기술을 확인했으면 상태를 바꾸고(주시 → 신규변화 / 도입검토), 최근확인 날짜·메모를 입력 (저장 버튼 없음 — 자동 저장·팀 실시간 공유)
  3. 대상 추가 — 새로 감시할 기술은 각 표 아래 + 추가로 등록, ✕로 삭제

⭐ 추천 — AITOM 발전을 위한 트래킹 운영 방안

  1. 우선순위①기술 + ②입찰을 먼저 돌리세요 — AITOM 고도화·수주에 직결됩니다. ③(제품·시장)은 월 1회 요약으로 가볍게.
  2. 오너십스터디 'AI 에이전트 영역 담당자'가 오너. 격주 로그 작성을 담당제 업무로 고정 (스터디 운영안의 "기술 트렌드 포함" 지적을 이걸로 충족).
  3. 개발 연결상태를 '도입검토'로 바꾼 항목은 그 주에 AITOM 개발 백로그 티켓으로 전환 — 트래킹이 관찰로 끝나지 않고 실제 개발로 이어지게.
  4. 핵심 무기AITOM 골든 평가셋(회귀 테스트) 구축 — 우리 대표 시나리오 20~30개로 평가셋을 만들어, 새 sLLM·RAG기법·프레임워크가 나올 때마다 동일 셋으로 비교. 기술 갭을 '느낌'이 아니라 '점수'로 측정.
  5. 분기 1회경쟁제품 Teardown — Dify·Langflow를 실제 설치해 AITOM과 기능 대조표 작성 → 차별화·따라잡기 항목 도출.
  6. 표준 선점MCP는 지켜보지 말고 선제 지원 — 커넥터 지원을 로드맵 상단에. 표준이 기본이 되면 미지원은 곧 탈락 요건.
  7. 역트래킹실주 사유·데모 실패·고객 불만을 기술 백로그로 환류 — "왜 졌나"가 다음 고도화 항목이 됩니다.
  8. 보고 리듬월 1회 '경쟁·기술 동향 1페이지'(②낙찰 + ③신호 + 골든셋 점수 추이)로 대표 보고.
